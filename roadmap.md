## Тесты

- ✅ Составная команда «открой Google Chrome, а в нём Telegram» больше не проходит
  через медленную GUI-цепочку `focus → Ctrl+L → type_text → clipboard`: известный
  сервис открывается одним проверяемым `open_url_in_browser` прямо в установленном
  Chrome, без LLM и повторного планирования между шагами. Низкоуровневый `type_text`
  больше не зависает при попытке прочитать занятый системный clipboard.
- ✅ Кнопка Stop стала настоящей отменой: `CancelledError` больше не проглатывается
  ToolRunner и немедленно обрывает агентный/recovery-цикл; React показывает состояние
  остановки, блокирует повторные клики, сбрасывает `busy` по `request_cancelled` и
  добавляет в диалог явное сообщение «Задача остановлена».
- ✅ Починен голосовой сценарий «открой absidian …» → «да»: частые STT-искажения
  Obsidian нормализуются до маршрутизации, короткое подтверждение продолжает последнюю
  исполнимую цель вместо нового chat-запроса, а `application` / `app` / `program`
  приводятся к обязательному `app_name` до проверки схемы. Служебные ответы провайдера
  вроде `User Safety: safe` считаются пустым ответом и переключают Nova на следующий
  доступный маршрут, а не показываются пользователю.
- ✅ Системный стиль Nova сжат до 1–3 коротких фраз: без каталога способностей, саморекламы, emoji,
  повтора запроса и дежурного «чем ещё помочь». Экспериментальный Windows SAPI удалён; тембр снова только Silero.
- ✅ Устранена ложная «медленность Groq» при wake-word по свежему runtime-логу: запрос к GPT OSS 120B
  ушёл в `20:07:07`, но его ответ не мог обработаться до `20:08:46` — точно до окончания четырёхминутной
  фоновой загрузки PyTorch/Silero. Тяжёлый TTS больше не прогревается в критическом startup-пути: Core, Groq,
  живые статусы и инструменты остаются отзывчивыми, а локальный голос лениво инициализируется только
  после того, как текстовый ответ уже отправлен в UI.
- ✅ Исправлена двухминутная задержка wake-команды на Windows/Realtek по реальному
  runtime-логу: порог окончания речи раньше оказывался ниже измеренного фонового шума,
  поэтому запись всегда доходила до максимального лимита, после чего PortAudio ждал
  graceful drain входного буфера до переключения режима. Теперь конец фразы определяется
  после 0,9 сек. тишины с порогом выше noise floor, готовый input stream завершается через
  немедленный `abort`, а чат сразу показывает «Услышала Нова» → «Фраза записана» →
  «Команда распознана» ещё до планирования моделью.
- ✅ Исправлен невидимый live-progress в React: конфликт общего CSS-класса `progress`
  с карточкой события сжимал каждый подробный этап до двухпиксельной полосы. Теперь в
  чате читаемо показаны context/routing/model/planning/execution/replanning/verification,
  фактические выбранные tools, безопасные имена аргументов, ошибки и процент выполнения.
  Безопасный resolver также исправляет только однозначный formatting drift имени tool
  (`OpenApplication`, `OPEN-APPLICATION` → `open_application`), поэтому модель больше не
  получает ложный `TOOL_NOT_FOUND` из-за регистра, но Nova не угадывает чужую capability.
- ✅ Adaptive Provider Swarm: Settings в реальном времени показывает общее и доступное
  число ключей Groq/OpenRouter/Gemini, независимые parallel lanes, активные запросы и
  готовность critic. Для каждого Nova-managed ключа можно задать собственный model ID;
  Core сохраняет соответствие «ключ → модель», использует override при маршрутизации и
  безопасно подхватывает изменившиеся free-модели без пересборки приложения.
- ✅ Ресурсный scheduler масштабирует только ограниченные бюджеты полезной работы по
  реально доступным независимым ключам: до 6 параллельных read-only специалистов,
  больше model/tool/context budget при большем пуле и жёсткие верхние пределы. Manager
  остаётся единственным исполнителем действий; reviewer сводит результаты, отдельный
  critic проверяет intent/доказательства/ложный успех и может запросить ровно одну
  ревизию вместо бесконечного агентного цикла.
- ✅ Исправлен блокирующий cold-start после добавления субагентов: обработчик `delegate_subagents` теперь подключается до строгой валидации `ToolRegistry`, поэтому Core больше не падает с `Для схем отсутствуют обработчики`. Тот же порядок исправлен во встроенном reasoning-loop режиме; реальный stdio-sidecar собрал 82 инструмента, поднял runtime-сервисы и оставался жив после 8 секунд.
- ✅ Voice input arbitration: Vosk wake word и обычный STT теперь используют
  единственную эксклюзивную microphone lease; смена режима ждёт закрытия прежнего
  PortAudio stream, а Ctrl+Shift+Space игнорирует автоповтор клавиатуры. Wake word
  и ручной голосовой ввод больше не могут самопроизвольно переключать друг друга.
- ✅ Live voice UX: Core передаёт React UI живой уровень микрофона и фазы
  `waiting / recording / transcribing`; над composer появилась Siri-подобная
  waveform-панель с явным индикатором записи и кнопкой остановки. Обычный STT
  больше не съедает первые слова секундной калибровкой, а Vosk понимает частые
  варианты распознавания «Нова» (`ново`, `нава`, `наува`).
  Во время собственного TTS панель явно показывает паузу микрофона и активную
  echo-защиту вместо ложного состояния «слушаю».
- ✅ Parallel Subagent Team v1: сложные многосоставные запросы автоматически получают
  intent-guardian, execution-architect и failure-hunter; параллелизм ограничивается
  реально доступными независимыми API-ключами/квотами (до 6), запросы распределяются
  по provider/model lanes, а reviewer возвращает главному агенту единый план. Субагенты
  аналитические и read-only: реальные действия, permissions и итоговая проверка остаются
  у главной Nova. В UI видны создание команды, роли, назначенные модели и reviewer-сводка.

# Режимы автономности и Tavily recovery (09.08.2026)

- [x] В настройках появились три реальных режима разрешений: «Полный доступ», «Только опасные» и «Спрашивать всегда».
- [x] Выбранный режим сохраняется локально, передаётся Nova Core через окружение и применяется в едином PermissionManager ко всем локальным и MCP-инструментам.
- [x] «Полный доступ» пропускает пользовательские approval-gates, но не отменяет жёсткие системные запреты и запрет автономных side effects в режиме «Nova рядом».
- [x] Рекомендуемый режим спрашивает только перед внешними отправками, выполнением команд, разрушительными и другими рискованными действиями.
- [x] Строгий режим запрашивает подтверждение перед каждым tool call, включая операции чтения.
- [x] При неуверенной расширенной маршрутизации Nova получает Tavily с повышенным приоритетом и сначала исследует незнакомый публичный сервис/API, а не сразу просит повторить запрос.
- [x] Локальные пути, файлы, clipboard, контакты, сообщения, токены и другой приватный контекст исключены из автоматического Tavily recovery.
- [x] Telegram resolver и goal ledger больше не требуют отдельное текстовое «да»: решение о подтверждении принимает только выбранный PermissionManager, поэтому в «Полном доступе» resolve_chat сразу продолжается реальным send_message.
